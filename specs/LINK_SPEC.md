# SDKWork Hub Link Standard

- Version: 1.0
- Status: active
- Scope: gitlink granularity, two-stage source model, pins, sparse checkout, lock file, stage-2 split criteria
- Related: `HUB_SPEC.md`, `CATALOG_SPEC.md`, `VERIFICATION_SPEC.md`, `../sdkwork-specs/DEPENDENCY_MANAGEMENT_SPEC.md`, `../sdkwork-specs/SDK_SPEC.md`, `../sdkwork-specs/SDK_WORKSPACE_GENERATION_SPEC.md`, `../sdkwork-specs/REPOSITORY_BASELINE_SPEC.md`

This standard defines how SDK sources enter the hub. The hub links sources; it never copies them.

## 1. Granularity Constraint

A gitlink (git submodule, tree mode `160000`) mounts a repository root at a path. It cannot mount a subdirectory of a repository.

Rules:

- `sdks/<path>` `MUST` be either a repository root mounted as a gitlink, or an authored directory listed in `HUB_SPEC.md` section 4. It `MUST NOT` be a partial checkout, junction, symlink, or copied tree.
- The hub `MUST NOT` use `file:`, `link:`, symlinks, junctions, or working-tree copies to present SDK source.
- SDK source under a module repository `sdks/` subtree remains reachable at `<gitlink>/sdks/<sdk-family>`; the hub `MUST` record that relative path in the catalog rather than creating a path alias.

## 2. Two-Stage Source Model

| Stage | Path | Points to | When |
| --- | --- | --- | --- |
| 1 | `sdks/modules/<module>` | SDK-owning module repository | Current model |
| 2 | `sdks/<sdk-family>` | Independent SDK repository | After the family is split out |

Rules:

- Stage 1 `MUST` be the default. A module repository owns the `sdks/` workspace that generates its families; splitting it is not a precondition for hub use.
- Stage 2 entries `MUST` be introduced one family at a time and `MUST` reference a repository that already owns that family end to end: authority OpenAPI, `sdk-manifest.json`, component spec, generation scripts, and release pipeline.
- Stage 2 `MUST NOT` leave the family duplicated in the original module repository. The module repository `MUST` consume the released SDK package and `MUST` remove the local family in the same coordinated change.
- A catalog entry `MUST` declare `source.stage` as `1` or `2` and `source.path` relative to the hub root.
- Agent-facing context `MUST NOT` depend on the stage. Skills and MCP resolve the source path from the catalog, never from a hard-coded `sdks/modules/...` pattern.

## 3. Sparse Checkout

Rules:

- A stage-1 gitlink `SHOULD` be materialized with sparse checkout limited to its `sdks/` subtree, so a module repository's application source is not fetched into the hub working tree.
- Sparse configuration is local state. It `MUST NOT` be committed as a requirement for correctness; the lock and catalog `MUST` be sufficient without it.
- The hub `MUST NOT` require `node_modules`, build output, or generated test artifacts from a linked repository.

## 4. Pin And Lock

`sdks/lock.json` is the only pin authority.

```json
{
  "schemaVersion": 1,
  "kind": "sdkwork.hub.lock",
  "stage": 1,
  "repos": [
    {
      "module": "sdkwork-iam",
      "stage": 1,
      "url": "https://github.com/sdkwork-ai/sdkwork-iam.git",
      "path": "sdks/modules/sdkwork-iam",
      "commit": "<40-hex>",
      "sdkFamilies": ["sdkwork-iam-app-sdk", "sdkwork-iam-backend-sdk", "sdkwork-iam-open-sdk"]
    }
  ]
}
```

Rules:

- `commit` `MUST` be a full 40-character commit SHA. Branch names, tags, short SHAs, and `HEAD` are forbidden as pins.
- `repos` `MUST` be sorted by `module`; each `module` and each `path` `MUST` be unique.
- `url` `MUST` be the canonical upstream URL. Machine-local paths are forbidden.
- `sdkFamilies` `MUST` list exactly the family directory names present at `<path>/sdks/` for that commit.
- The lock `MUST` be regenerated by `hub link add` / `hub link update`, never hand-edited except resolving a documented merge conflict that preserves both pins.
- A pin `MUST` advance only forward. Reverting a pin is a governed exception under `GOVERNANCE_SPEC.md` section 5.

## 5. Commands

```bash
node tools/hub.mjs link list
node tools/hub.mjs link add <module> [--url <url>] [--ref <commit-or-ref>]
node tools/hub.mjs link update <module> [--ref <commit-or-ref>]
node tools/hub.mjs verify
```

Rules:

- `link add` `MUST` add the submodule at `sdks/modules/<module>`, update `sdks/lock.json`, and refuse to continue when the module already exists or when the URL is not an upstream repository URL.
- `link update` `MUST` fetch the requested ref, resolve it to a commit, update the submodule entry, and rewrite the lock.
- Both commands `MUST` fail fast when `git` is unavailable or the repository is not on `main`.
- After any link change, `catalog/` `MUST` be recompiled and committed in the same change.

## 6. Stage-2 Split Criteria

A family qualifies for split when all of the following hold:

- The family's TypeScript consumer package is published and consumable from the registry, or the language packages declared in its manifest have a documented release channel.
- Its authority OpenAPI, `sdk-manifest.json`, `component.spec.json`, and generation scripts move together into the new repository.
- The original module repository consumes the released package and removes the local family.
- A release train entry exists that pins both the module repository and the new SDK repository for the transition window.
- The split is recorded as an ADR under `docs/architecture/decisions/`.

Priority order:

1. Published TypeScript families (about 130 at initialization).
2. Families with an authority OpenAPI and a stable manifest.
3. Remaining families stay in stage 1 until their owner requests a split.

## 7. Prohibited Patterns

- Vendoring, copying, or archiving SDK source in the hub.
- Committing a worktree, junction, symlink, or `file:` dependency.
- Tracking a branch instead of a commit.
- Presenting a stage-1 module path as if it were an SDK repository.
- Editing generated SDK output or family metadata from the hub.

## 8. Verification

```bash
node tools/hub.mjs verify
```

The gate `MUST` fail when a gitlink path is outside `sdks/`, a lock entry is unsorted, a commit is not a full SHA, a lock module has no matching gitlink, a gitlink has no lock entry, or a linked checkout's `HEAD` differs from its pin.
